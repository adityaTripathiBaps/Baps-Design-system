# Button

Triggers a single action or navigation.

<ResourceTabs />

`baps-button` wraps PrimeNG's `p-button` and themes it globally — this page documents that usage against the `MyBky` preset (`libs/ui-kit/src/lib/theme/baps.theme.ts`), verified pixel-for-pixel against Figma node [22465:93605](https://www.figma.com/design/yY5bmcEifXbcCwhauoiy6Y/%F0%9F%9F%A2-MyBKY?node-id=22465-93605).

The wrapper also carries a second visual skin — `brand="sampark"` — implementing the Sampark Portal button set from Figma node [13197:91897](https://www.figma.com/design/xc0L2xnREMgjyb5XcKyLIz/%F0%9F%9F%A2-Sampark-Portal?node-id=13197-91897).

## Theming

Unlike most components here, Button has a real component-token tier: the Sampark skin is authored as PrimeNG design tokens (`SAMPARK_BUTTON_TOKENS`) rather than component CSS, so it is re-pointed from `libs/tokens` without touching the component.

**Why primary does not change in dark.** A filled button supplies its own ground, so the white-on-maroon pair is unaffected by what is behind it — unlike a text colour that sits directly on the page. The secondary treatment *is* affected, because its background is close to the page, and it switches accordingly. This is the opposite of the gap documented on [Alert](?path=/docs/components-alert--docs), where a foreground colour was left unchanged over a ground that moved.

## Accessibility

### Screen Reader

- Renders a native `<button>`, so it is announced with the button role without any extra wiring.
- Set `ariaLabel` when the button is icon-only — with no visible `label` there is nothing to announce.
- `disabled` sets the native attribute, which also removes the button from the tab order. Prefer it over CSS-only disabling, which leaves a focusable control that does nothing.
- `loading` does **not** imply `disabled`. Pair them where the action genuinely cannot be retriggered, otherwise a second activation fires while the first is still in flight.

## When Not to Use

| Need | Use | Not this |
| --- | --- | --- |
| Navigate to another route or URL | `baps-link` | `baps-button` — it renders a `<button>`, so there is no href, no middle-click, no "open in new tab" |
| One primary action plus related secondary ones | `baps-split-button` | Two adjacent buttons |
| A setting that applies immediately, with no submit | `baps-toggleswitch` | A button you re-label between states |
| A choice among options inside a form | `baps-checkbox` / `baps-select` / `baps-listbox` | A row of buttons acting as a picker |
| Laying out a row of page-level actions | `baps-toolbar` as the container | Buttons positioned with ad-hoc margins |

`[link]="true"` *looks* like a link but is still a `<button>` — when the destination is a URL, use `baps-link`.
