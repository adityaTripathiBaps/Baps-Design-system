# Input

The text-input field pattern: a **label**, the **control**, and optional **helper** or **error** text. BAPS provides wrapper components and directives (such as `bapsInputText`, `baps-floatlabel`, `baps-iconfield`, `baps-inputicon`, and `baps-message`) wrapping their respective PrimeNG equivalents and themes them globally against the `MyBky` preset (`libs/ui-kit/src/lib/theme/baps.theme.ts`).

MyBKY fields use the **pill radius** (`99px`) with 36px height and 1.5px hover/focus borders; Sampark uses `4px` radius, a 32/28/40px height scale, and keeps a 1px border in every state. Switch the **Design system** toolbar to Sampark to render it live — the skin lives in `libs/ui-kit/src/lib/styles/components/input/_input-sampark.scss`, which re-points the `--input-*` variables that `_input.scss` drives every state through.

The two other controls that share this stories file have their own pages: [Listbox](?path=/docs/components-molecules-listbox--docs) and [Menu Item](?path=/docs/components-molecules-menu-item--docs).

## Usage

```html
<div class="field">
  <label for="email">Email</label>
  <input
    id="email"
    bapsInputText
    [(ngModel)]="email"
    [invalid]="emailCtrl.invalid && emailCtrl.dirty"
    placeholder="you@baps.dev"
    aria-describedby="email-help"
  />
  @if (emailCtrl.invalid && emailCtrl.dirty) {
    <baps-message id="email-help" severity="error" variant="simple" size="small">
      Enter a valid email
    </baps-message>
  } @else {
    <small id="email-help">We'll never share your address.</small>
  }
</div>
```

## When Not to Use

| Need | Use | Not this |
| --- | --- | --- |
| A single on/off value in a form | `baps-checkbox` | A text input with "yes"/"no" |
| A setting that applies the moment it is flipped | `baps-toggleswitch` | `baps-checkbox`, which implies a save step |
| A number inside a known range | `baps-slider` | A numeric input with min/max validation |
| Picking a person from the directory | `baps-users-dropdown` | `baps-listbox` of names — it has no avatar/role row |
| A submit-level summary of everything that failed | `baps-alert` at the top of the form | A stack of `baps-message` elements standing in for one |
| Explaining a field on hover only | `bapsTooltip` | Helper text, which is always visible and adds height |
| Displaying a value the user cannot change | Plain text, or `baps-tag` for a status | A disabled input — disabled controls are skipped by screen readers |

## Accessibility

- Every field needs a programmatic label: a `<label for>` matching the input `id`, a `baps-floatlabel`, or an `ariaLabel`. A `placeholder` is **not** a label — it disappears on input.
- Associate error text with the field via `aria-describedby` pointing at the message element, so screen readers announce the error when the field gains focus.
- Indicate required fields in the label text (or `aria-required`), not by color alone.
- Don't disable a field to communicate "not yet" — disabled controls are skipped by screen readers; use read-only or contextual messaging instead.
