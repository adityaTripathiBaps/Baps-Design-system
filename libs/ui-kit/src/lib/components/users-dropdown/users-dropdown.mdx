# Users Dropdown

A select-style dropdown built for picking a person.

<ResourceTabs />

The Sampark Portal **Users Dropdown** (Figma node [13197:89016](https://www.figma.com/design/xc0L2xnREMgjyb5XcKyLIz/%F0%9F%9F%A2-Sampark-Portal?node-id=13197-89016)). Like the FormField Sampark dropdowns it presents a **trigger field** — 40px, 4px radius, chevron — and clicking it opens a floating **panel**: a search field over a scrollable list of [`baps-menu-item`](?path=/docs/components-menuitem--docs) rows showing an avatar and a name over a role. Data-driven via `users`; the search filters by title and subtitle client-side. Picking a row sets `value`, emits `valueChange`, and closes. Click-outside and `Esc` also close.

## Usage

<CodeBlock
  filename="assign-karyakar.component.ts"
  language="typescript"
  code={`import { BapsUsersDropdown, type BapsUserOption } from '@org/ui-kit';

@Component({
imports: [BapsUsersDropdown],
template: \`
<baps-users-dropdown
[users]="users"
[(value)]="selected"
placeholder="Select karyakar"
searchPlaceholder="Search"
brand="sampark"
/>
\`,
})
export class AssignComponent {
users: BapsUserOption[] = [
{ id: 1, name: 'Rajesh Patel', role: 'Regional Admin' },
{ id: 2, name: 'Priya Shah', role: 'Centre Lead' },
];
selected: unknown = null;
}`}
/>

## Accessibility

### Screen Reader

The trigger is a native `<button>` carrying `aria-haspopup="listbox"` and `aria-expanded`, so its open/closed state is announced without any consumer wiring. The panel is `role="listbox"`, and gains `aria-multiselectable` in checkbox mode. Grouped lists wrap each group in `role="group"` labelled by the group's label, and the visible group title is `aria-hidden` so the label is not read twice. The search field is labelled by `searchPlaceholder`.

The component supplies no name for the trigger itself — pass one from the outside (`aria-label`, or a `baps-form-field` label), otherwise the trigger announces only its current value.

The framework implementations currently differ at the option layer. The React
`BapsUsersDropdown` gives every row `role="option"`, `aria-selected`, roving
`tabIndex`, and Arrow/Home/End navigation. The Angular wrapper still renders
plain `baps-menu-item` rows without `role="option"`; that pre-existing Angular
accessibility gap is documented here rather than hidden by the React work.

For Angular consumers that require a fully keyboard-driven picker today, use
`baps-select` until the existing wrapper closes its option-role and arrow-key
gap. React consumers can use `BapsUsersDropdown` directly.

## When Not to Use

| Need                                               | Use instead                                                    | Why not this                                                                                                                                                                                                                                                                         |
| -------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Picking a plain value with no avatar or subtitle   | `baps-select`                                                  | The avatar column and two-line row are the entire reason this component exists                                                                                                                                                                                                       |
| A list that stays open in the page, not in a panel | `baps-listbox`                                                 | This component is a trigger plus an overlay                                                                                                                                                                                                                                          |
| A list of _actions_ rather than values             | `baps-menu-item` in your own container, or `baps-split-button` | Selecting here means "this is now the value", not "do this"                                                                                                                                                                                                                          |
| Showing who is already assigned, read-only         | `baps-avatargroup`                                             |                                                                                                                                                                                                                                                                                      |
| Server-side search over thousands of users         | Not this component                                             | `filtered` is a synchronous `Array.filter` over the whole `users` input on every keystroke — no debounce, no virtualization, no lazy loading. `searchChange` emits the query so a consumer _could_ refetch, but the internal filter still runs over whatever `users` currently holds |
| Keyboard-driven option navigation                  | Not this component                                             | Arrow-key navigation through the list is explicitly out of scope                                                                                                                                                                                                                     |
