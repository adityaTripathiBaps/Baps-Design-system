# Chip

A compact label for a selected value, a filter, or an entity. `baps-chip`
wraps PrimeNG's `p-chip`.

Figma calls this component **Badge** — MyBKY
[22465:95582](https://www.figma.com/design/yY5bmcEifXbcCwhauoiy6Y/%F0%9F%9F%A2-MyBKY--Phase-1-?node-id=22465-95582),
Sampark
[13197:90701](https://www.figma.com/design/xc0L2xnREMgjyb5XcKyLIz/%F0%9F%9F%A2-Sampark-Portal?node-id=13197-90701).

This is the **same visual object a multiselect renders for each selection**, so
both read from the grey tag tokens rather than a second near-identical set of
greys. The multiselect's own chips are styled under `.p-multiselect` in
`styles/components/select`, so nothing here reaches them and nothing there
reaches a standalone chip — but if one moves, the other should.

Severity ramps, sizes, counts and chevrons belong to [`baps-tag`](/docs/components-tag--docs).

## Usage

```html
<baps-chip label="Robbinsvile" />
```

```html
<baps-chip
  label="Satsang Network"
  [removable]="true"
  (remove)="drop('satsang')"
/>
```

MyBKY is the unscoped default; add `brand="sampark"` only to opt one instance
in on an otherwise-MyBKY page.

### A design-system icon inside a chip

`icon` takes a **CSS class**, not a glyph name — it is passed straight to
PrimeNG, which renders `<span [class]="icon">`. So `icon="pi pi-clock"` works
and `icon="add-circle"` silently renders an empty span.

For a `baps-icon` glyph, use the content slot:

```html
<baps-chip label="Badge Text">
  <baps-icon name="add-circle" [size]="14" />
</baps-chip>
```

## Anatomy

The **remove** control is taken out of flow and hidden until hover, so a
read-only list of chips is not littered with crosses and no chip resizes when
one appears.

## Migration — four inputs moved out, 30 September 2026

Chip used to carry a severity ramp, a size ramp, a count disc and a trailing
chevron. Those belong to `baps-tag`, which already had all four, so chip is now
the plain label-and-remove atom it started as.

This is a breaking change, and how your app finds out depends on how the
attribute was written. Measured under `strictTemplates: true`: a **bound** input
(`[count]="8"`) fails the build with `NG8002: Can't bind to 'count' since it
isn't a known property of 'baps-chip'`, while a **literal** attribute
(`severity="warning"`) produces no error at all — Angular leaves the unknown
attribute on the element, so the app builds and the chip quietly renders plain
and grey. Grep your templates for the literal form; the compiler will not find
it for you.

| Removed from `baps-chip` | Use instead |
| --- | --- |
| `severity` | `baps-tag` `severity` — see the value map below |
| `size="xs \| s \| m \| l"` | `baps-tag` `size` — same four steps, same heights (18 / 22 / 26 / 32px), so the value carries over unchanged |
| `count` | `baps-badge` with `type="counts"` and the number in `value`. A different component with its own vocabulary, not a renamed input |
| `chevron` | `baps-tag` `chevron` — same boolean |

Severity values do not carry over one for one, because tag names its severities
the way PrimeNG does:

| Old chip `severity` | New `baps-tag` |
| --- | --- |
| `grey` (the default) | leave `severity` unset — grey is tag's base, not a modifier |
| `primary` | `severity="contrast"` — tag's own note records that Figma's navy "Primary" chip is `contrast` |
| `secondary` | `severity="secondary"` |
| `info` | `severity="info"` |
| `success` | `severity="success"` |
| `warning` | `severity="warn"` |
| `error` | `severity="danger"` |

```html
<!-- Before -->
<baps-chip label="Pending" severity="warning" size="m" [count]="8" />

<!-- After -->
<baps-tag value="Pending" severity="warn" size="m" />
<baps-badge type="counts" [value]="8" />
```

## When Not to Use

- **A status label with a severity.** Use [`baps-tag`](/docs/components-tag--docs)
  — it has severity ramps, sizes, counts and chevrons.
- **A count with no label.** A bare number on a corner is
  [`baps-badge`](/docs/components-badge--docs), not a chip.
- **Something clickable that navigates.** A chip is a label, not a control —
  use a [link](/docs/components-link--docs) or a
  [button](/docs/components-button--docs).

## Accessibility

- The remove control is PrimeNG's own button and keeps its keyboard behaviour.
  It is only *visually* hidden at rest — `visibility` plus `opacity`, not
  `display: none` — so it stays in the tab order.
- `disabled` suppresses the remove on hover as well as dimming the chip.
- Colour is never the only channel — every chip keeps its label.
