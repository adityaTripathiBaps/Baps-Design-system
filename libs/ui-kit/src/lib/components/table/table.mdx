# Table

Data table with sorting, filtering, pagination, selection, and row grouping. `baps-table` wraps PrimeNG's `p-table` (`primeng/table`) and forwards its template-driven API almost entirely as-is — column markup (`<th>`/`<td>` pairs, sort/frozen directives) is authored by the *consumer* via `ng-template pTemplate="header|body|groupheader|emptymessage|..."`, not generated by this wrapper. The Sampark visual skin lives in a global stylesheet, `_table-sampark.scss` (`libs/ui-kit/src/lib/styles/components/table/`), scoped to `baps-table.baps-sampark` or a `.baps-ds-sampark` ancestor — see [Brand Behavior](#brand-behavior) for why MyBKY has no matching layer.

## Usage

```html
<baps-table [value]="rows" brand="sampark" [paginator]="true" [rows]="10">
  <ng-template pTemplate="header">
    <tr>
      <th pSortableColumn="name">Name <p-sortIcon field="name" /></th>
      <th>Status</th>
    </tr>
  </ng-template>
  <ng-template pTemplate="body" let-row>
    <tr>
      <td class="baps-table-cell-lead">
        <span class="baps-table-cell">{{ row.name }}<small>{{ row.description }}</small></span>
      </td>
      <td><baps-tag brand="sampark" [value]="row.status" /></td>
    </tr>
  </ng-template>
  <ng-template pTemplate="emptymessage">
    <tr><td colspan="2">No rows match these filters</td></tr>
  </ng-template>
</baps-table>
```

## When Not to Use

| Need | Use instead | Why not the table |
| --- | --- | --- |
| A single-column list of choices | `baps-listbox`, or `baps-select` when it should collapse | A table's header/cell/border machinery is dead weight for one column of values |
| Picking a person by name + role | `baps-users-dropdown` | Already has the avatar row, the search field and the close-on-Escape behavior |
| A real hierarchy — arbitrary depth, lazy child nodes | `p-treetable` (not wrapped in this library) | `baps-table`'s grouping is one flat subheader level with a CSS-drawn spine; there is no hierarchical data model underneath |
| Paging controls with no table attached | `baps-paginator` on its own | It is a standalone component; `WithPagination` shows it driving a table from outside |
| A handful of key/value facts about one record | `baps-card` | One-row tables read as a layout hack |
| Column visibility / pin / reorder UI | `baps-table-column-config` | It exists as its own component and is already wired to this one in `WithColumnConfig` |

Also don't reach for it as a responsive layout primitive — it is the least adaptive component in the library, for the reasons below.

## Accessibility

- Renders PrimeNG's native `<table>` markup — header/body semantics come from `p-table` itself.
- Icon-only controls (`.baps-table-action`, group/row toggles, the column-settings trigger) all carry explicit `aria-label`/`aria-expanded` in every story; follow that pattern for new columns.
- The `Default` story's "Toggle columns" header cell pairs a `pi-objects-column` icon with a visually-hidden `<span class="p-hidden-accessible">` label — do the same for any icon-only header affordance.
- `.baps-table-action:focus-visible` gets an explicit 2px outline in the Sampark skin; don't suppress it.
