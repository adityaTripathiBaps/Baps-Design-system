# Using the BAPS design system in your project

This guide walks through everything an application needs to consume the BAPS UI kit:
installing the library, wiring up the theme, loading fonts and tokens, and using each
component. It applies to any Angular app inside this Nx workspace (member database,
event management, donation management, Satsang).

## At a glance

| | |
|---|---|
| Package | `@org/ui-kit` (workspace library) |
| Framework | Angular 21, standalone components only — no NgModules |
| Underlying UI library | PrimeNG 21 with a customized Material preset (`MyBky`) |
| Design tokens | `@org/tokens` — Style Dictionary, generated `tokens.ts` + `tokens.css` |
| Icons | primeicons (PrimeNG inputs) and Lucide (product UI) |
| Selector prefix | `baps-` for components, `baps` (no hyphen) for directives |

## 1. Install / reference the library

Inside this workspace nothing needs to be installed — the library resolves through the
TypeScript path alias defined in `tsconfig.base.json`:

```json
"paths": {
  "@org/ui-kit": ["./libs/ui-kit/src/index.ts"]
}
```

Every public component, directive, and the theme preset are exported from that single
entry point:

```ts
import { BapsButton, BapsAvatar, BapsTag, MyBky } from '@org/ui-kit';
```

Your app must also have the peer dependencies available (already present at the
workspace root):

| Dependency | Version |
|---|---|
| `@angular/core`, `@angular/common` | `^21.2.0` |
| `primeng` | `21.1.3` |
| `@primeuix/themes` | `2.0.3` |
| `primeicons` | `^7.0.0` |

## 2. Bootstrap: register the theme

The design system ships a PrimeNG preset called `MyBky`
(built with `definePreset(Material, …)` in `libs/ui-kit/src/lib/theme/baps.theme.ts`).
Register it once in your `app.config.ts`. This is the same configuration Storybook uses,
so components render identically in your app and in these docs.

```ts
// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideAnimationsAsync } from '@angular/platform-browser/animations/async';
import { providePrimeNG } from 'primeng/config';
import { MyBky } from '@org/ui-kit';

export const appConfig: ApplicationConfig = {
  providers: [
    provideAnimationsAsync(),
    providePrimeNG({
      ripple: true,
      theme: {
        preset: MyBky,
        options: {
          darkModeSelector: '.baps-dark',
          cssLayer: {
            name: 'primeng',
            order: 'theme, base, components, primeng, utilities, app-styles',
          },
        },
      },
    }),
  ],
};
```

Notes:

- Use `provideAnimationsAsync()` (from `@angular/platform-browser/animations/async`),
  not `provideAnimations()`.
- The CSS layer order matters. Put your own application styles in the `app-styles`
  layer so they can override PrimeNG without specificity fights:

```scss
@layer app-styles {
  html {
    font-size: 14px; // rem baseline: tokens are authored at 1rem = 16px,
                     // PrimeNG components are scaled to 14px
  }
}
```

## 3. Load styles, tokens, and fonts

Add these to your application (via `angular.json` / `project.json` `styles`, or imports
in your root stylesheet):

```ts
// Icon font used by PrimeNG components (loading spinners, input icons)
import 'primeicons/primeicons.css';

// Roboto — fallback base font for the Material preset
import '@fontsource/roboto/400.css';
import '@fontsource/roboto/500.css';
import '@fontsource/roboto/700.css';

// Design token CSS custom properties (generated by Style Dictionary).
// Note: reference the built file by path — the @org/tokens exports map
// does not expose ./build, so a package subpath import will not resolve.
import '../../libs/tokens/build/css/tokens.css'; // adjust relative to your app
```

Run `pnpm nx build tokens` first if `libs/tokens/build/` doesn't exist yet — the CSS
is generated, not checked in.

Then include the layout SCSS partials from
`libs/ui-kit/src/lib/styles/layout/` in your global stylesheet:

- `_fonts.scss` — the `@font-face` for **Inter Variable** (bundled TTF, weight axis
  100–900). Make sure the font asset
  `styles/layout/fonts/Inter-VariableFont_opsz,wght.ttf` is served by your app
  (copy it via the `assets` config, the same way Storybook serves it via `staticDirs`).
- `_common.scss` — sets `--font-family`, and `--font-feature-settings` with the
  17 OpenType features enabled globally. **Always preserve these.**

Font roles:

| Font | Role |
|---|---|
| Inter Variable | All UI text. Weights: 400 body, 500 labels/badges, 600 headings/buttons, 700 prominent titles |
| Roboto | PrimeNG/Material fallback only |
| Instrument Serif | Target — editorial moments (landing H1, Satsang pull-quotes). Not yet installed |
| JetBrains Mono | Target — receipt numbers, PAN, reference IDs. Not yet installed |

## 4. Use the components

All components are standalone. Import the class into your component's `imports` array
and use the `baps-` tag. Never import PrimeNG components directly in product code —
always go through the `baps-` wrapper so theming and future migrations stay centralized.

```ts
import { Component } from '@angular/core';
import { BapsButton, BapsTag } from '@org/ui-kit';

@Component({
  selector: 'app-member-toolbar',
  imports: [BapsButton, BapsTag],
  template: `
    <baps-tag value="Active" severity="success" />
    <baps-button label="New member" severity="primary" />
  `,
})
export class MemberToolbarComponent {}
```

### Component reference

| Component | Selector | Import | Notes |
|---|---|---|---|
| Button | `baps-button` | `BapsButton` | `label`, `icon`, `iconPos`, `severity`, `outlined`, `text`, `raised`, `rounded`, `size`, `loading`, `disabled`, `fluid`. Projects `ng-content`. |
| Avatar | `baps-avatar` | `BapsAvatar` | Image, icon, or label avatars |
| Avatar group | `baps-avatar-group` | `BapsAvatarGroup` | Stacks multiple avatars |
| Badge | `baps-badge` | `BapsBadge` | Numeric / status badge |
| Overlay badge | `baps-overlay-badge` | `BapsOverlayBadge` | Badge anchored on another element |
| Tag | `baps-tag` | `BapsTag` | Categorical labels |
| Toggle switch | `baps-toggle-switch` | `BapsToggleSwitch` | Implements `ControlValueAccessor` — works with `ngModel` and reactive forms |
| Input text | `input[bapsInputText]` | `BapsInputText` | Directive; exposes `variant`, `invalid`, `fluid` |
| Float label | `baps-float-label` | `BapsFloatLabel` | Floating label wrapper for inputs |
| Icon field | `baps-icon-field` | `BapsIconField` | Wraps an input with an icon |
| Input icon | `baps-input-icon` | `BapsInputIcon` | The icon inside an icon field |
| Message | `baps-message` | `BapsMessage` | Inline validation / info message |

See the **Components** section in the sidebar for live examples, controls, and
per-component docs.

### Pasting an example into your app

Every snippet in these docs and in each component's **Show code** is the markup
only. Three things it cannot carry across, in the order they will bite you:

1. **The import.** The tag is inert without its class in `imports`, and Angular
   says `NG8001: 'baps-split-button' is not a known element`. The class name is
   the selector in PascalCase with the dashes dropped — `baps-split-button` is
   `BapsSplitButton`, `baps-tree-select` is `BapsTreeSelect`. Every component
   exports from `@org/ui-kit` directly, so one import line covers any number of
   them.

2. **Brackets on non-string inputs.** A plain attribute is *always* a string, so
   `inline="true"` sets a boolean input to the string `"true"` and Angular
   rejects it with `TS2322: Type 'string' is not assignable to type 'boolean'`.
   Booleans and numbers need the bracket form — `[inline]="true"`, `[count]="8"`
   — while text inputs are fine as bare attributes: `label="Save"`,
   `severity="primary"`.

3. **Anything the snippet references on the component.** `[(ngModel)]="date"`
   needs a `date` property and `FormsModule` in `imports`; `(click)="save()"`
   needs a `save()` method. Angular reads these as expressions against *your*
   component and fails with `TS2339: Property 'date' does not exist`.

All three fail at build time, and the dev server keeps serving the **last good
bundle** when a build fails — so the page does not show an error, it just stops
changing. If a paste seems to do nothing, read the terminal.

### Buttons

```html
<baps-button label="Save" severity="primary" />
<baps-button label="Cancel" severity="secondary" [outlined]="true" />
<baps-button label="Delete" severity="danger" [text]="true" />
<baps-button label="Send receipt" icon="pi pi-envelope" [loading]="sending" />
```

Note the brackets on `[outlined]` and `[text]`. See
[Pasting an example into your app](#pasting-an-example-into-your-app) — they are
boolean inputs, and `outlined="true"` hands them the four-character string
`"true"` instead.

Button labels are short, sentence-case imperatives: "Register", "Save",
"Send receipt", "Join Satsang".

### Form fields

The form-field pieces compose. `bapsInputText` is a directive applied to a native
`<input>`, so the element stays a real input for forms and accessibility:

```ts
import {
  BapsInputText,
  BapsFloatLabel,
  BapsIconField,
  BapsInputIcon,
  BapsMessage,
} from '@org/ui-kit';
```

```html
<!-- Plain input -->
<input bapsInputText placeholder="Full name" />

<!-- Floating label -->
<baps-float-label>
  <input bapsInputText id="pan" [(ngModel)]="pan" />
  <label for="pan">PAN</label>
</baps-float-label>

<!-- Input with icon -->
<baps-icon-field>
  <baps-input-icon styleClass="pi pi-search" />
  <input bapsInputText placeholder="Search members" />
</baps-icon-field>

<!-- Validation message -->
<input bapsInputText [invalid]="panExists" />
@if (panExists) {
  <baps-message severity="error" text="This PAN already exists on record" />
}
```

Error copy is concrete ("This PAN already exists on record") — never
"Something went wrong".

### Forms integration

`BapsToggleSwitch` implements `ControlValueAccessor`, so it binds directly:

```html
<!-- Template-driven -->
<baps-toggle-switch [(ngModel)]="remindMe" />

<!-- Reactive -->
<baps-toggle-switch [formControl]="attendance" />
```

## 5. Design tokens

Never hard-code colors, spacing, or radii. Consume tokens instead:

- **In TypeScript / theme work**: import from `@org/tokens` (generated
  `tokens.ts`).
- **In CSS/SCSS**: use the custom properties from `tokens.css`
  (e.g. `var(--border-1)`, `var(--radius-lg)`, `var(--space-5)`).

Token source lives in `libs/tokens/src/source/*.json`; Style Dictionary generates the
outputs. If you change source JSON, rebuild the tokens project — never edit generated
files by hand.

Key visual rules the tokens encode:

- **4px spacing grid** — most gaps are 8 / 12 / 16 / 24px. `--space-8` (32px) between
  unrelated blocks, `--space-4` (16px) within a card.
- **Radii** — 10px (`--radius-md`) for inputs, chips, buttons; 14px (`--radius-lg`)
  for large cards and modals; 20px (`--radius-xl`) for photos.
- **A card at rest**: white background, `--border-1` hairline, `--radius-lg`, no
  shadow. Shadows belong only to floating elements (dropdowns, modals, toasts).
- **Accent discipline** — one product-scoped accent per surface, never two in the same
  component: slate teal (admin/default), clay (donations), indigo (Satsang), sage
  (events/seva).

## 6. Dark mode

Dark mode is class-driven. Toggle the `.baps-dark` class on a root element
(usually `<html>`) and the preset switches color schemes:

```ts
document.documentElement.classList.toggle('baps-dark', prefersDark);
```

## 7. Icons

- **PrimeNG component inputs** (`icon`, `loadingIcon`, `styleClass` on
  `baps-input-icon`) take primeicons classes: `pi pi-search`, `pi pi-check`.
- **Product UI icons** use Lucide, stroke-based at `stroke-width="1.75"`,
  sized 16px in dense tables, 20px in nav, 24px in tab bars, 32px in empty states.
  Icons inherit `currentColor` — never re-colour them for decoration.
- No emoji and no raster/PNG icons anywhere in product UI.

## 8. Writing UI copy

The components carry the visuals; copy rules keep the voice consistent:

- Sentence case for all labels: "New member", "Mark attendance" — not Title Case,
  not ALL CAPS. (`.eyebrow` is the only ALL-CAPS class, for table headers and tags.)
- Dates day-first: "25 April 2026". Times 12-hour with a space: "6:30 PM".
- Currency with Indian digit grouping: "₹ 2,100".
- No emoji, no exclamation marks (except rare confirmations), no vague errors.

## 9. Contributing a new component

1. Generate/author it under `libs/ui-kit/src/lib/components/<name>/`.
2. Follow the wrapper pattern: a standalone component (the default in Angular 21 — no
   `standalone: true` flag needed) that imports the PrimeNG component, forwards the
   relevant `@Input()`s in the template, and projects content with `<ng-content>`.
3. Prefix the selector with `baps-` (components) or `baps` (directives).
4. Export it from `libs/ui-kit/src/index.ts` — that file is the public API.
5. Add `<name>.stories.ts` and `<name>.mdx` next to the component.
6. Verify in Storybook: `pnpm nx storybook storybook-host` (port 4402).

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Components render unstyled | `providePrimeNG` with the `MyBky` preset is missing from `app.config.ts` |
| Wrong font (Roboto everywhere) | `_fonts.scss` / `_common.scss` not included, or the Inter Variable TTF isn't being served |
| Icons show as squares | `primeicons/primeicons.css` not imported |
| Your CSS loses to PrimeNG styles | Put app styles in the `app-styles` layer (see the `cssLayer.order` in section 2) |
| Text looks too large | Missing the 14px rem baseline: `@layer app-styles { html { font-size: 14px; } }` |
| Animations warn or overlays misbehave | `provideAnimationsAsync()` missing from providers |
