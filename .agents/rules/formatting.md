# Formatting & Code Style Rules

## Tooling

- **Prettier** owns formatting. Config is `.prettierrc` — `{ "singleQuote": true }`.
  Do not reformat by hand and do not override it per file.
- **ESLint** owns linting (`eslint.config.mjs`, Nx flat config).

```bash
npx nx lint ui-kit
npx prettier --write <file>
```

`.prettierignore` excludes generated output — `libs/tokens/build/`,
`libs/tokens/src/generated/`, `dist/`, `documentation.json`. **Never hand-edit
anything in those.**

## The backtick rule — run the guard before you build

```bash
node tools/check-styles-literals.mjs
```

**A backtick inside a component's `styles:` or `template:` literal terminates
the literal.** TypeScript then parses the rest of the stylesheet as code, and
the errors point at the CSS, never at the comment that broke it:

```
ERROR TS2304: Cannot find name 'avatar'.
ERROR TS1005: ',' expected.
```

This cost real time four separate times in one session, always the same way:
writing a comment that quotes a class or property in Markdown style.

```ts
styles: `
  /* WRONG — the backticks around \`order\` end the literal */
  /* Set by \`order\`, so the label lands second */

  /* CORRECT — no backticks inside a styles literal */
  /* Set by the order property, so the label lands second */
`;
```

Same rule in `template:` literals. Prose comments in `.md` and `.mdx` files are
unaffected — use backticks freely there.

The guard covers 145 files and runs in under a second. Put it before
`nx build ui-kit` in any script that touches component styles.

## Comment style

This library's comments carry **why**, not what. A rule with its reason attached
survives a refactor; a bare value gets "cleaned up".

```ts
/* CORRECT */
// order 3, explicitly: an item with no order defaults to 0 and would jump
// ahead of the label. PrimeNG renders its ng-content slot BEFORE
// .p-chip-label, which is why the DOM order and the visual order differ.

/* WRONG */
// set order to 3
```

Where a value came from a measurement or a Figma node, say so — the node id, the
measured number, the thing that was ruled out. Those notes are what stop the
same wrong fix being tried twice.

## TypeScript

- `strict` is on. No `any` in public API surface; `unknown` plus a narrow if you
  must.
- No non-null `!` on something a consumer supplies — make the input optional and
  handle the absence.
- Type-only imports use `import type`.
- Story files are excluded from `tsconfig.lib.json` and covered by
  `tsconfig.spec.json`, so **type-check stories with**:

```bash
npx tsc --noEmit -p libs/ui-kit/tsconfig.spec.json
```

A story that only fails there still breaks the Storybook build, so run it before
restarting Storybook.

## Line length and wrapping

Prettier decides. Comments wrap at roughly 80 columns to stay readable in a
side-by-side diff.

## Before committing

```bash
node tools/check-styles-literals.mjs
npx tsc --noEmit -p libs/ui-kit/tsconfig.spec.json
npx nx lint ui-kit
npx nx build ui-kit
```
